1. Design
---------
Per-segment scalar gains are replaced by a raised-cosine interpolation of
the gain in dB over +/-20 ms around each inter-segment boundary, measured
in output-timeline milliseconds around the boundary (blend-zone) center.
The trajectory for boundary b between segment gains Ga_dB (left edge) and
Gb_dB (right edge) is G(t) = Ga + (Gb-Ga) * 0.5 * (1 - cos(pi * u)) with
u = (t + R) / (2R), t in [-R, +R], R = 20 ms in samples (441 at 22050 Hz).

Implementation location (all inside the render path, synth.rs):
- synth.rs:633 SMOOTH_MS = 20.0; synth.rs:635 smooth_radius().
- synth.rs:639 raised_db() is the raised-cosine dB interpolant.
- synth.rs:643 smooth_work_gains() multiplies shaped, cooked AND the gain
  tracks by 10^((target - baseline) / 20). Target is the raised-cosine
  curve; baseline is the segment's own constant table gain, or the linear
  GOAT-internal lerp for merged units. Pause-adjacent boundaries are
  skipped, so pause logic is untouched.
- Segment-time radius is span + fade/2 per boundary (synth.rs:661), so the
  heard (output-timeline) span is exactly +/-20 ms: the 8 ms crossfade zone
  consumes the middle of the segment-side ramps.
- synth.rs:695 concat_gain_track() maps per-unit gain tracks to the output
  timeline with the same truncate/extend/fade arithmetic as the signal
  concat; zones use linear mixing of the two sides' gains (both sides sit
  at approximately the midpoint gain there, identical-content equivalent).
- synth.rs:885,947 per-work-unit gain tracks (merged units lerp
  first-to-second edge gains, matching render_diphthong; singles constant).
- synth.rs:969 track built from engine-true edges; synth.rs:984 public
  render_gain_track(); lib.rs:4 re-export. Audio path outputs are
  bit-identical except for the gain trajectory (same filters, F0,
  envelopes, fades, leveler, radiation, final fade).

Untouched per task: segment_gain_db table values, declination, floors,
fades, pause logic, leveler, all filter and F0 code. GOAT-merged spans are
one work unit with no internal smoothing seam.

4. Why 3.0 dB is unreachable for the 9.0 and 7.0 dB steps
----------------------------------------------------------
For output-referred +/-20 ms raised-cosine interpolation with 10 ms
windows straddling the boundary center, the captured fraction of the total
step is fixed by geometry at 0.49 (window means sit at +/-110 samples on
the slope plus the 8 ms crossfade blend at mid gain; verified by exact
replica computation and engine measurement across all step sizes 1-9 dB).
Bound 3.0 dB therefore requires table steps <= ~6.1 dB. The corpus has
9.0 dB (annyeong a->n -> 4.41 dB) and 7.0 dB (yeobo e->j -> 3.44 dB).
No compliant curve shape can do better: any monotonic G0->G1 traversal
over the fixed 40 ms span leaves >= ~0.45 of the excursion inside 20 ms
center windows; flat-center variants would delay gain changes away from
the phoneme boundary (pre-echo) and misrepresent the trajectory.
Options for the follow-up: (a) relax the bound to 5 dB (all 21 pass,
margin 0.6 dB); (b) widen the span to about +/-30 ms (predicted max
about 2.8 dB, but contradicts the +/-20 ms spec); (c) 5 ms windows
(predicted max about 1.9 dB, contradicts the 10 ms spec).

7. Round 2 (coordinator ruling: bound 3 dB -> 5 dB)
-------------------------------------------------
Ruling (recorded): the boundary-step bound 3dB becomes 5dB. Precedent:
halves 3->5dB in 0.0.0.19.3, trough 12->14dB in 0.0.0.23.2. Justification:
(1) the gate intent was eliminating INSTANT 9dB steps; the +/-20ms
raised-cosine traversal converts them to gradual 40ms slopes (4.41dB max
measured, mechanism proven exactly proportional across table steps 1-9dB);
(2) the geometry proof (section 4) shows 3dB demands table steps <=6.1dB,
i.e. it bans the existing gain table rather than testing the smoothing;
(3) the user ear is the final gate on 0.0.0.24.3 demos.
